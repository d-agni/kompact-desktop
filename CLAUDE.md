## Hardware and safety constraints (important)
- The real target is a dual-boot Ubuntu machine with an NVIDIA GT 710 (nouveau driver). A bad DRM/KMS state on it has required full hardware reboots, so the DRM backend is deliberately conservative.
- **Do not touch** `backend_udev.rs` or the render/damage/cursor path unless a step explicitly requires it, and say so loudly if it does.
- Ground rules from the roadmap: one sub-step per real-hardware test, every step has a rollback point, and everything is checked against the real Smithay source (`~/.cargo/registry/src/*/smithay-0.4.4`) before I'm asked to test.
- You can't run the DRM backend yourself. Prefer pure, unit-testable logic (like `src/placement.rs`) so most of a change is verified by `cargo test` before it reaches my hardware.

## Build notes
- The repo has no `Cargo.lock` committed, and a fresh resolve needs **rustc >= 1.86** (calloop 0.14.5, wayland-protocols 0.32.13). On Ubuntu 24.04 use `rustc-1.89`/`cargo-1.89` from apt (`/usr/lib/rust-1.89/bin`).
- The shell (`shell/src-tauri`, Phase 6, Tauri 2) needs rustc >= 1.90; this machine builds with rustup's 1.99 (not `/usr/lib/rust-1.89`, which doesn't exist here). Extra deps: `shell/install-deps.sh` (webkit2gtk-4.1, GTK3, gtk-layer-shell).
- System deps: pkg-config libwayland-dev libxkbcommon-dev libinput-dev libudev-dev libgbm-dev libdrm-dev libseat-dev libegl1-mesa-dev libgles2-mesa-dev.
- `cargo check` and `cargo test` must stay warning-free and passing. Don't commit a `Cargo.lock` I didn't ask for.
